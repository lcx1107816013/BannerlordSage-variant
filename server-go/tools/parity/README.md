# 差分等价测试（Differential parity harness）

**这个目录存在的唯一理由**：让"无损"这句话变成**可验证**的。

---

## 为什么普通的单元测试在移植里不够用

移植由谁写、测试就由谁写 —— 那么测试**只能证明"Go 与作者对原文的理解一致"**。
如果作者**读错了原文**，测试就会**和这个错误理解一致地全绿**。
这句话不是理论，**本项目实测撞到过**（见下）。

所以这里的**期望值不由人写**，而是**跑真正的 TypeScript 产生**，
冻结进 `fixtures.json`；Go 侧拿自己的输出**逐字节比对**。

---

## 怎么用

```bash
# 1) 由 TypeScript 生成期望值（每次改了被移植的 TS 都要重跑）
bun run server-go/tools/parity/gen_fixtures.mjs

# 2) Go 侧比对
cd server-go && go test ./internal/parity/ -v
```

输出（实测）：

```
  fts     cases: 59
  sandbox cases: 34
  sandbox rejections: 13
```

## 两个刻意的设计

**1. 期望值必须来自"执行原文"，不是"照抄原文"。**
- `PathSandbox.validateAndResolve` —— 直接 `import` 真文件 `src/utils/path-sandbox.ts`。
- `buildFtsQuery` —— 它是**模块私有**函数（`search-docs.ts` 与 `search-api-docs.ts` 各有一份），
  所以从源码里**按名字整段抽取**（花括号配对），写成临时 `.ts` 再 import。
  抽取失败**直接 FATAL** —— 上游一改名，这里**响亮地炸**，
  而不是静默产出一份"和什么都不匹配"的夹具。
  同时还**交叉校验**那两份拷贝彼此一致：**它们若分家，本身就是一条发现**。

**2. 空夹具必须判失败。**
夹具解析成功但为空，会让下面所有循环**空转通过** —— 这正是差分套件悄悄失效的经典方式。
所以 `load()` 显式拒绝空夹具。

## ★ 它一上线就抓到了什么（本次会话最重要的发现）

第一次跑，**FTS 的 3 个用例就红了**：

| 输入 | Go | TypeScript |
|---|---|---|
| `'"'` | `'""'` | `''` |
| `'""'` | `'""'` | `''` |
| `'" "'` | `'""'` | `''` |

**而真相是：最先那版 Go 代码是对的，错的是测试。**

- TS 的守卫**在去引号之前**判空；`'"'` 去引号后变成 `' '`，
  而 JS 里 `' '` 是**真值** ⇒ 守卫**不触发** ⇒ 一路走到 split/filter，
  空列表 join 出 `''`。（Go 里 `strings.Fields(" ")` 为空、`Join` 出 `""`，**自然一致**。）
- 我手写的单测断言 `'"'` → `'""'` —— 那是**我对 TS 的误读**。
- 测试"失败"了，于是我把**本来正确的代码改成去迎合错误的测试**。
- **我还在注释里把这次改动夸成"修掉了一个 bug"。**

**差分套件第一次运行就把这个错纠正了** —— 因为它比的是**跑出来的 TS**，
不是**我以为的 TS**。

> 教训：**测试的期望值如果是人写的，那它验证的是人的理解，不是代码。**
> 只要原文可以被执行，就该**执行它**来产生期望值。

## ★ F15：`env` 移植时抓到的 4 个真 divergence

### 1. 又是 `TrimSpace` —— 同一个陷阱，第二个单元踩到

```
normalizeGameId("\ufeffX")   go = "\ufeffx"   ts = "x"
```

Go 的 `unicode.IsSpace('\ufeff')` 是 **false**，JS 的 `trim()` **剪它**。
已改用 ECMAScript 集合。**从文件读到的 game id 带 BOM 是完全可能的，所以这条是可达的，不是理论。**

### 2. ★ 移植**静默丢掉了两个字段**

TypeScript 返回 **13** 个字段，Go 结构体只有 **11** 个 ——
`xmlParseReportPath` 与 `xmlParseReportMarkdownPath` **整个不见了**。

> **只比值不比键，永远抓不到这个** —— 所以测试**先断言字段集，再比值**。

### 3 & 4. 声明为"已知差异"，**不修**：Unicode 大小写折叠

```
normalizeGameId("İSTANBUL")   go = "istanbul"   ts = "i̇stanbul"
normalizeGameId("ΣΊΣΥΦΟΣ")     go = "σίσυφοσ"     ts = "σίσυφος"
```

JS 的 `toLowerCase()` 实现 **Unicode SpecialCasing**，Go 的 `strings.ToLower` 只有**简单映射**。
已逐 rune 核实：`U+0130` → Go `U+0069`，JS `U+0069 U+0307`；希腊尾 sigma `U+03C2` Go 不施加。

**故意不复现**：game id 是 slug，这些输入**在这个函数的真实定义域之外**，
而复现 SpecialCasing 等于**为不可能出现的输入内嵌一张大小写表**。
**差异被"声明"在测试里的一张表中** —— 每条记录 TypeScript 会产出什么，
**上游行为一变，这条就不再匹配、测试就报错**。**ASCII 全部逐字节一致。**

> **这是诚实的中间路线**：非预期的不一致 = **失败**；已声明的差异 = **有界、有理由、且不会悄悄扩大**。

### 根目录差异：**断言**而不是跳过

TS 从**自己的源码位置**推根目录；Go 是独立二进制、没有源码，所以从 `BLORE_ROOT` 或repo 标记走。
测试把 `BLORE_ROOT` 设成夹具记录的根，**前提不满足就 FAIL** ——
**所以这个比较永远不会"悄悄变得没有意义"。**

### 反向验证

| 注入的 bug | 结果 |
|---|---|
| `jsTrim` 换回 `TrimSpace` | **FAIL** ✅ BOM 那条，且**提示里点名了原因** |
| 去掉一个字段 | **FAIL** ✅ 字段集断言报出 |

## ★ F13：`report` 移植时抓到的三个真问题

全部是"**先有兄弟套件的方法论、这次照着做、于是当场抓到**"。

### 1. ★ 真实 divergence：JS `trim()` ≠ Go `TrimSpace`

```
tag=string value="\ufeff"   go = "\ufeff"   ts = "unknown"
```

两者**修剪的是不同的集合，而且两个方向都不一样**：

| 码点 | JS `trim()` | Go `TrimSpace` |
|---|---|---|
| U+FEFF BOM / ZWNBSP | **剪** ✔ | 不剪 ✗ ← **JS 剪，Go 不剪** |
| U+0085 NEL | 不剪 ✗ | **剪** ✔ ← **Go 剪，JS 不剪** |

**所以换用 `strings.TrimSpace` 是两头都错**，而且**任何拉丁文本的用例都看不见**。
我原来的注释**声称两者一致** —— 测量说不是。已实现 ECMAScript 的**精确集合**（`jsTrim`），
并**把两个方向都钉进测试**（U+0085 那条专门用来拦"顺手简化成 TrimSpace"的人）。

### 2. 数字格式化：JS `String(n)` 不是任一个 Go verb

| 值 | JS | Go `'g'` | Go `'f'` |
|---|---|---|---|
| `1e-5` | `0.00001` | `1e-05` ✗ | `0.00001` ✓ |
| `1e-7` | `1e-7` | `1e-07` ✗ | `0.0000001` ✗ |
| `1e20` | `100000000000000000000` | `1e+20` ✗ | ✓ |

**单个 verb 都不对**：JS 只在 `|x| ≥ 1e21` 或 `|x| < 1e-6` 时才用指数，且**指数不补零**。
已照这两条规则实现，**两个边界都钉了测试**。

### 3. ★★ 夹具本身会"看起来像覆盖"

三次连环缺陷，**每一次都是"套件打印了 compared N cases，但其实没测到东西"**：

| 缺陷 | 症状 | 怎么发现 |
|---|---|---|
| 生成器**只发了 result、没发 inputs** | Go 拿空串去比，12 个渲染用例里 8 个是空的 | 断言"inputs 必须存在且真实" |
| 生成器**把带 tag 的对象直接喂给 TS** | `String({...})` = `"[object Object]"`，**10 个期望值是垃圾**；另 2 个抛 `value?.trim is not a function` | 断言期望值里**不含** `[object Object]` |
| `JSON.stringify` **把 NaN 写成 null** | Go 解出 `0`，报 `nan: 0` vs `nan: NaN` —— **夹具缺陷伪装成移植缺陷** | 用 replacer 统一处理非有限数 |

**共同教训**：**"比较了 N 个用例"不等于"N 个用例都有效"。**
夹具必须有**存在性断言**（非空、非哨兵、inputs 真实），否则覆盖是假的。
